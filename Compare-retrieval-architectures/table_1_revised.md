## 2.7. Comparative Architecture Analysis

The DLI-LLM framework intersects conceptually with retrieval-augmented language models and memory-integrated transformer architectures. Table 1 distinguishes memory representation, integration mechanism, and the scope of gradient propagation. These dimensions are considered separately because an external index does not necessarily imply independently optimized retrieval, and transformer-layer memory access does not necessarily imply differentiable updates to stored representations (Lewis et al., 2020; Guu et al., 2020; Wu et al., 2022).

**Table 1. Architectural comparison of DLI-LLM with selected retrieval-augmented and memory-integrated language models.**

| Architecture | Memory representation and integration | Learning and gradient scope | Principal distinction from the proposed DLI-LLM framework | Evidence status |
|---|---|---|---|---|
| **DLI-LLM (this work)** | Latent key–value bank accessed by projected hidden states; temperature-scaled softmax read and content-dependent gated fusion within transformer layers. A shared token/document space is assumed. | The dense formulation supports gradients through continuous queries, scores and values when these are trainable. The training treatment of stored embeddings and the sparse/quantized selection mechanism remain unspecified. | Proposes combining layer-integrated latent retrieval with content-dependent fusion and a shared token/document representation. The contribution and benefits of this combination require comparison with the architectures below. | Conceptual formulation; no implementation or benchmark results. |
| **Product-Key Memory (Lample et al., 2019)** | Trainable product-structured keys and value vectors; efficient exact top-k lookup with softmax-weighted aggregation, integrated into selected transformer layers in place of feed-forward blocks. | Query networks, subkeys and values are trainable; updates operate through selected scores and values. Hard top-k membership is distinct from a dense differentiable distribution. | Already establishes learned latent key–value access inside transformer layers. Its memory consists of learned parameters rather than a source-linked bank of ingested documents. | Evaluated on large-scale language modeling, inference speed and memory usage. |
| **Memorizing Transformers (Wu et al., 2022)** | Cached key–value representations of previous inputs; approximate nearest-neighbor retrieval and attention over selected memories, fused with local attention within a transformer layer. | Stored memories are non-differentiable. A learned per-head scalar gate combines memory and local attention; the gate is not token-content dependent in the reported formulation. | Already combines hidden-state retrieval and gated internal fusion. DLI-LLM instead proposes a content-dependent fusion gate and differentiable memory access, with a shared token/document bank. | Evaluated on long-document language modeling, memory-size scaling and retrieval behavior. |
| **Persistent-memory attention (Sukhbaatar et al., 2019)** | Learned persistent memory vectors augment self-attention and provide an alternative to the feed-forward layer. | Persistent memory vectors are learned during training. | Establishes persistent latent memory inside transformer attention, without the proposed ingestion and joint addressing of token and document memories. | Evaluated on character- and word-level language modeling. |
| **REALM (Guu et al., 2020)** | External document-embedding index; retrieved text conditions a knowledge-augmented encoder. | The masked-language-model objective jointly trains the retriever and reader during pretraining, using retrieved-candidate approximation and asynchronous index refreshes. Fine-tuning freezes the document encoder while updating the query side. | Establishes task-informed retrieval learning despite an external index. DLI-LLM proposes hidden-layer latent-value fusion rather than conditioning the reader on retrieved document text. | Evaluated on open-domain QA, retrieval recall and index-staleness ablations. |
| **RAG (Lewis et al., 2020)** | Dense index of passage embeddings and source text; an encoder–decoder generator conditions on retrieved passages, with sequence- or token-level latent-document marginalization. | The query encoder and generator are jointly fine-tuned; the document encoder and index remain fixed in the reported implementation. | Retrieves source passages for generator conditioning rather than querying a latent value bank from transformer-layer hidden states. External indexing does not preclude joint optimization of the query encoder and generator. | Evaluated on QA, generation and fact verification, including human assessment of generation. |
| **RETRO (Borgeaud et al., 2022)** | External text-chunk retrieval combined with a differentiable neighbor encoder and chunked cross-attention inside the language model. | The BERT retriever is frozen; the retrieved-context encoder and integration pathway are differentiable. | Already integrates retrieved evidence into transformer computation. DLI-LLM proposes learned hidden-state addressing of latent values rather than fixed-retriever text-chunk access. | Evaluated on language modeling and downstream QA with a large retrieval corpus. |
| **kNN-LM (Khandelwal et al., 2020)** | Datastore of language-model hidden-state keys and next-token values; the neighbor distribution is interpolated with the language model's output distribution. | Post-hoc nearest-neighbor augmentation; the reported headline language-model improvement requires no additional model training. | Integrates retrieval at the output-probability level rather than through a latent memory block within transformer layers. | Evaluated on language modeling and datastore-based domain adaptation. |
| **Recurrent Memory Transformer (Bulatov et al., 2022)** | Special memory tokens carry representations between sequence segments through ordinary transformer processing. | Training learns memory operations through the transformer; the memory is a recurrent state rather than a separately indexed document bank. | Provides segment-to-segment memory propagation rather than content-addressed access to the proposed token/document bank. | Evaluated on language modeling and tasks requiring longer-sequence processing. |
| **Titans (Behrouz et al., 2025)** | Neural long-term memory learns from historical context and is combined with attention through alternative integration designs. | The memory learns at test time; this differs from the frozen-index inference configuration proposed in DLI-LLM's appendix. | Provides an adaptive neural memory rather than an explicit index of token/document key–value records. It is a contrasting memory-update design, not an equivalent retrieval implementation. | Evaluated on language modeling and other sequence tasks, including long-context needle retrieval. |

**Notes.** The table compares architectural properties, not performance under a common evaluation protocol. Evidence reported for a comparator does not validate DLI-LLM or establish relative superiority. Differentiable weighting of retrieved values, learning of the retrieval query, and gradient propagation into stored memories are separate properties. Hard top-k selection and quantization require an explicit gradient treatment if used during training. The DLI-LLM row describes the dense mechanism in Sections 2.2–2.5; the top-k, product-quantized and cross-attention configuration in Appendix A is a proposed implementation variant, not an experimentally established equivalent. Product-key structure in PKM should not be conflated with product quantization of a document index.

Taken together, these comparisons position DLI-LLM as a proposed combination of existing memory and retrieval mechanisms rather than as the first integration of retrieval into transformer computation. Its principal empirical question is whether jointly trainable latent retrieval and content-dependent fusion improve evidence use or computational efficiency relative to matched internal-memory and retrieved-text baselines. The feasibility of a shared token/document space and the quality–cost trade-off of sparse retrieval remain open questions.
