1. How this differs from the first benchmark

  • One source release: only Nazario_5 is used. MixedEmail is excluded because its positive label also contains generic spam. Legitimate examples remain negatives; “phishing-only” does not mean a one-class test.
  • Matched population: both new split schemes use the same 1,600 Nazario emails from the original seed-42 cohort: 814 source-positive and 786 source-negative. New seeds change the split, not the sampled population.
  • Matched features and models: subject + body, capped at 6,000 characters; same six fixed baselines and four text conditions as before. No selection by a phishing-keyword rule is used to redefine the positive set.
  • Reserved validation: 1,280 training, 160 validation and 160 test examples per seed and scheme. Baseline hyperparameters remain fixed; validation is not used to select winners.
  • Separate transformer run: the existing six-model DistilBERT sweep still uses the original random splits. It was temporarily paused for CPU/memory contention during this repeat and resumed. No new grouped DistilBERT scores are claimed or queued.

2. What the inferred groups mean

Group construction is label-blind and frozen before split assignment. Email addresses, URLs, numbers and long identifiers are masked in a canonical text representation. A graph connects messages with canonical word unigram/bigram TF-IDF cosine similarity ≥0.80, or matching nontrivial normalized subjects (at least 15 characters and three words). Its connected components define template groups. Groups are built using the entire fixed cohort as a split-construction step; classifier vectorizers are still fitted only on training examples.

The cohort has 1,337 inferred groups, including 160 non-singleton groups; the largest has 14 messages. Three stratified random-fold seeds are compared with three stratified group-fold seeds. All members of a detected group remain together in train, validation or test in the grouped arm.

4. Noise and truncation

As before, the four conditions are clean text, 5% and 15% expected per-letter obfuscation, and the first 80 whitespace-delimited words. Test text alone is perturbed. These are synthetic stressors, not verified real-world attack distributions. Full results are in the archive.

5. Group-aware statistical tests

On the grouped seed-42 test fold only, all 15 model pairs are compared across four conditions: 60 tests. Each inferred group is a resampling unit. Group-level paired label swaps test the difference in model error counts, with exact enumeration when at most 16 groups contribute nonzero differences, otherwise 10,000 Monte Carlo swaps. Holm correction covers these 60 tests as a separate, explicitly scoped exploratory family; it does not jointly correct every comparison from earlier experiments.

F1 differences have separate, pointwise 95% percentile intervals from 1,000 paired group-bootstrap resamples. These intervals are not multiplicity-adjusted. On clean seed 42, logistic regression minus SVM is 0.00621 F1, with a pointwise group-bootstrap interval 0 to 0.02274. Group-swap p=1.0 and Holm p=1.0: no supported advantage. SVM minus character LR is −0.000076, interval −0.01863 to 0.02015, Holm p=1.0.

The uncertainty calculation assumes that the proxy groups are suitable independent exchangeability/resampling units. Unknown relationships across groups can violate that assumption. Repeated split seeds overlap and are not independent campaigns. There is no inferential random-versus-grouped comparison because the held-out emails differ.

6. Recorded failures

For clean grouped seed 42, word logistic regression has no errors on 160 source-labeled test messages. SVM has one false negative (hash 289ee430…, group proxy-0388). Naïve Bayes and character LR each have one false positive on the same message (hash 4d101e8c…, group proxy-0494). These are prediction disagreements with the source labels, not independently confirmed real incidents. Keyword rules miss 54 of 81 source-positive messages and flag two source-negative messages.

The archive's failure_cases.csv identifies every seed-42 error by full-text hash, inferred group, source label, prediction and test condition. Raw messages and live phishing links are not redistributed. No unverified root-cause narrative is assigned to these cases.

7. What remains to meet the literal request

Verified campaigns: provide publisher/analyst campaign membership or an evidence-backed annotation mapping, not just message IDs, sender domains or this similarity clustering. Each verified campaign must be wholly assigned to one split.

Audited phishing-only positives: independently adjudicate whether each positive is a deceptive credential/payload/payment-diversion attempt, distinguishing generic spam, ordinary marketing and ambiguous messages. Ambiguous examples must be excluded or separately scored. Source membership alone cannot certify all of those distinctions.

label_campaign_audit.csv supplies the 1,600 message hashes, source labels and proxy groups, with explicitly blank adjudicated_label and publisher_campaign_id columns. Every row is marked not independently reviewed. These blanks are a record of missing ground truth, not completed annotations. The next strict repeat should use those audited fields, then freeze split assignments before any further model tuning.

8. Dataset check and provenance

The check did not verify a release satisfying all requirements simultaneously. The original Nazario phishing collection is publisher hand-classified but has no verified campaign mapping. PhishBench provides benchmarking software and small class-directory fixtures, not a verified campaign annotation in the inspected examples. Phishing Pot includes multiple unsolicited-message categories and no verified campaign-ID mapping; it was not treated as strict binary phishing truth. These are bounded checks, not proof that no suitable release exists.

This executed repeat uses the existing Nazario_5 CSV, attributed to Champa, Rabbi and Zibran's Phishing Email: 11 Curated Datasets. Its SHA-256 was verified against the first run. Code, grouped split manifest, leakage counts, 144 evaluation rows, 60 tests, failures and the missing-label audit sheet are packaged together.
