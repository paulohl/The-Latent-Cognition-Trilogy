Execution contract

Two training corpora × seeds 42,43,44; three full fine-tuning epochs each. Every model uses the original 1,280 training / 160 validation / 160 test hashes. Four in-domain test conditions and one cross-corpus test per model: 30 planned evaluations. Input CSV SHA-256 values and all split labels were verified before training.

DistilBERT-base uncased; learning rate 5e−5; weight decay .01; up to 512 tokens after the same 6,000-character input cap. CPU-safe microbatch 2 × 8 accumulation steps gives effective batch 16. Float32, dynamic padding, length-grouped training, scaled dot-product attention. These execution changes preserve the effective batch and max length, but not bitwise equivalence to the paper's batch implementation.

Validation is evaluated after each epoch; the final epoch is always used. Test conditions are evaluated only after all three epochs of that model. The pretrained base checkpoint is public; this is not the author's private fitted model. Label/source confounding and overlapping split caveats from the original report still apply.

Files and resuming

Progress is recorded in run_status.json and this HTML file. Reopen the file to see later updates; no automatic notification is promised. Completed job folders contain metrics, per-email hash-only predictions, training logs and fitted model weights. Completed jobs are skipped on restart; interrupted jobs resume from the last 40-step checkpoint when available. If the environment stops, the process stops; the launcher is not a recurring schedule.

After all jobs finish, comparisons against the six baselines use seed 42 only, with 1,000 stratified paired bootstrap F1 intervals and exact McNemar tests. The old 150 baseline tests and the 60 new comparisons share a globally Holm-corrected family of 210 tests. Unadjusted F1 intervals do not imply adjusted significance.
